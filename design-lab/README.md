**เนื้อหาที่ preview** — เป็นหน้าจอจำลองจริง ไม่ใช่ตารางสีเปล่าๆ:
1. **Dashboard** — topbar, sidebar, KPI 4 ใบ, กราฟเส้น, กราฟแท่ง, ตารางค่าเดินเครื่อง, chip สถานะ
2. **ฟอร์มบันทึกงาน** — input/select/textarea/date, สถานะ error, toggle, ปุ่ม 5 แบบ, toast 3 ระดับ
3. **รายการ + รายละเอียด** — list, กล่องยืนยัน, สถานะว่าง (empty), สถานะกำลังโหลด (skeleton)
4. **คลังส่วนประกอบ** — แท็บ · ตัวเลือกแบ่งช่อง · เมนูหล่น · แบ่งหน้า · คำอธิบายลอย · ตัวเลขแจ้งเตือนบนไอคอน ·
   accordion · การ์ดกดได้ทั้งใบ · แถบความคืบหน้า · เส้นทางหน้า · checkbox/radio · ช่องค้นหา · กลุ่มรูปผู้ใช้ ·
   กราฟวงแหวน · กราฟแท่งซ้อนชั้น
5. **มือถือ 390px** — bottom nav, การ์ด 2 คอลัมน์, sidebar ยุบหาย

> ทั้ง 3 ทิศทางใช้ **HTML ชุดเดียวกัน 100%** (clone มาจาก `<template>` เดียว) ต่างกันแค่ค่า CSS variable

## D4 · Supasit.A Studio — ตัวจริงรอบที่ 4

พี่ A ดู 3 ทิศทางแล้วเลือกเป็น **สูตรผสม** ซึ่งประกอบขึ้นเป็น D4 (เปิดไฟล์มาเจอตัวนี้เป็นค่าเริ่มต้น):

| องค์ประกอบ | เอามาจาก | ค่าที่ใช้จริง |
|---|---|---|
| โครง สัดส่วน จังหวะ | **D3 Studio** | การ์ดมุม 13px · เงาบางชั้นเดียว + เส้น hairline · ตัวอักษร 15px/1.6 · motion 0.16s · ตารางเส้นบาง |
| ชุดสี | เลือกใหม่ 28 ส.ค. | **น้ำเงินหมึก `#1D4ED8`** · อำพัน `#8A6410` · พื้น `#F7F9FC` (เดิมเป็นมิ้นท์ ดูเหตุผลหัวข้อ "โทนสี") |
| ปุ่ม | **D2 Clarity** | ทรงแคปซูล `border-radius: 999px` |
| ฟอนต์ | Noto Sans Thai | |
| ความแน่น | สบายตา | |
| ธีม | สว่างเป็นหลัก | (มืดออกแบบครบ ไม่ใช่ invert) |

> **หมายเหตุ:** ทุกค่าสีในระบบผ่านการวัด contrast ด้วยเครื่อง ไม่ใช่กะด้วยตา
> (contrast ต่ำคือหนึ่งในสาเหตุที่ทิ้งระบบรอบก่อน) ดูผลล่าสุดในหัวข้อ "ผลตรวจล่าสุด" ด้านล่าง

**ถ้ายังไม่ถูกใจตรงไหน แก้ได้ที่ตัวแปรเดียว** เช่น
- ปุ่มแคปซูลดูขัดกับ input มุม 9px → เปลี่ยน `--r-btn` เป็น `22px` หรือเปลี่ยน `--field-radius` เป็น `999px`
- อยากให้แน่นขึ้น → กดปุ่ม "แน่น" ที่แถบบน
- สีเข้ม/อ่อนไป → ขยับ `--accent` แล้วหนูจะตรวจ contrast ให้ใหม่

## โทนสี — ทำไมถึงต้องออกจากเขียว (28 ส.ค. 2569)

ก่อนสรุป design system หนูตรวจประวัติสีแบรนด์จาก git แล้วเจอ 2 เรื่องที่วัดได้:

**1 · รื้อมา 3 รอบ แต่สีแบรนด์แทบไม่เคยเปลี่ยน**

| ระบบ | สีแบรนด์ | Hue | ที่มา |
|---|---|---|---|
| Tactile Plant UI | `#0d9488` | 175° | commit `af0a4e0` |
| Instrument Grade | `#12857C` | 175° | commit `31d56af` |
| Supasit.A Studio (มิ้นท์) | `#007F70` | 173° | D4 เดิม |

ห่างกัน **2 องศา** — ตาแยกไม่ออก รื้อโครง ฟอนต์ เงา มุมไปหมดแล้ว 3 รอบ
แต่สิ่งที่คนจำแอปได้มากที่สุดคือสี ซึ่งไม่เคยถูกเปลี่ยนเลย นี่คือคำอธิบายที่เป็นไปได้มากที่สุด
ว่าทำไมความรู้สึก "แอปดูซ้ำกันทุกตัว" ไม่เคยหายไปสักรอบ

**2 · เขียวแบรนด์ชนกับเขียว "ปกติ" — เป็นปัญหาเชิงฟังก์ชัน ไม่ใช่รสนิยม**

- accent มิ้นท์ (hue 173°) ห่างจาก ok "ปกติ" (hue 148°) แค่ **25°**
- จำลองตาที่แยกเขียว-แดงไม่ได้ (deuteranopia ~8% ของผู้ชาย): เหลือ **5°** → ปุ่ม "บันทึก" กับ chip "ปกติ" กลายเป็นสีเดียวกัน
- ขัดกับกติกาที่ตั้งไว้เองว่า "สีบอกสถานะ" — ถ้าสีแบรนด์กับสีสถานะเป็นสีเดียวกัน กติกานั้นก็อ่านไม่ออก

**พี่ A เลือก "น้ำเงินหมึก" `#1D4ED8` เป็นสีแบรนด์ของ Supasit.A Studio แล้ว** (28 ส.ค. 2569)
— เป็นค่าฐานของ D4 · badge · starter · เอกสารทั้งชุด
โทนที่เหลือยังกดเทียบได้ในปุ่ม **โทนสี** (ใช้ได้กับ D4 เท่านั้น — D1-D3 คงสีเดิมไว้เป็นตัวอ้างอิง):

ตรวจด้วย Playwright + Chromium ทั้ง 4 ทิศทาง × สว่าง/มืด:

## หมายเหตุทางเทคนิค (เผื่อพี่ A อยากรู้ว่าโค้ดข้างในทำงานยังไง)

- **`data-dir` / `data-theme` / `data-font` / `data-density` บน `<html>`** — สลับทิศทางคือแค่เปลี่ยนค่า attribute
  แล้ว CSS จะหยิบชุด variable คนละชุดมาใช้ ไม่มีการโหลดหน้าใหม่หรือแตะ DOM เลย
- **Container query (`@container`)** — เป็นหัวใจที่ทำให้กรอบมือถือ 390px แสดง layout มือถือจริงได้
  โดยไม่ต้องย่อหน้าต่างเบราว์เซอร์ เพราะ responsive ผูกกับ *ความกว้างของกล่อง* ไม่ใช่ *ความกว้างของจอ*
  (ถ้าใช้ `@media` แบบเดิม กรอบมือถือจะโชว์ layout เดสก์ท็อปย่อส่วน ซึ่งหลอกตา)
- **ธีมครบ 3 สถานะ** — `:root` (สว่าง) · `@media (prefers-color-scheme: dark)` + `:not([data-theme="light"])` (ตามระบบ) ·
  `[data-theme="dark"]` (ผู้ใช้เลือกเอง) — ไม่ใช่รสนิยม แต่เป็นข้อบังคับ ไม่งั้นแอปจะเพี้ยนบนบางเครื่อง
- **`min-width: 0` บน grid item** — ค่าเริ่มต้นของ grid item คือ `auto` ทำให้ตารางที่กว้างเกินดันทั้งหน้าให้เลื่อนแนวนอน
  บั๊กนี้เจอตอนทดสอบจริงในกรอบมือถือ (`scrollWidth 538 > clientWidth 370`) แก้แล้วเหลือ 0
- **ไอคอนเป็น inline SVG sprite** — ไม่พึ่ง CDN เปิดไฟล์แบบ offline ก็ยังครบ
- **คีย์ `localStorage` ขึ้นเวอร์ชันเป็น `dpk2:`** ตอนเพิ่ม D4 — ไม่งั้นค่าที่เบราว์เซอร์จำไว้จากรอบก่อน (D1 + Anuphan)
  จะทับค่าเริ่มต้นใหม่ แล้วพี่ A จะเปิดมาไม่เจอตัวจริง
- **`localStorage` อยู่ใน `try/catch` เสมอ** — โหมดส่วนตัวของเบราว์เซอร์โยน error ได้ ถ้าไม่ดักหน้าจะพังทั้งหน้า
