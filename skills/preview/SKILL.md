# /preview — ดูของจริงก่อนขึ้น production

> เรียกด้วย `/preview` เท่านั้น

## ทำไมต้องมี

QA checklist §24.5 บอกให้ "ทดสอบบนมือถือจริง ไม่ใช่แค่ DevTools" แต่เดิมทำได้เฉพาะ
**หลัง** ของขึ้น production แล้ว เพราะ push main = ขึ้น production ทันที
คำสั่งนี้ทำให้ทดสอบได้ก่อน

## ลำดับการทำงาน

1. เช็คว่าอยู่บน branch อะไร — **ถ้าอยู่บน `main` ให้หยุดแล้วถามก่อน**
   preview เกิดจาก pull request ไม่ใช่จาก main
2. ถ้ายังไม่มี branch → เสนอชื่อ branch ตามงานที่ทำอยู่ แล้วให้ `sa-git-manager` สร้าง+push
3. เปิด PR (ถ้ายังไม่มี) — body บอกสั้นๆ ว่าเปลี่ยนอะไรและอยากให้ลองอะไรบนมือถือ
4. รอ workflow `Preview` แล้วดึง URL จากคอมเมนต์ใน PR
5. **ส่ง URL ให้พี่ A พร้อมบอกว่าให้ลองอะไรบ้าง** — เจาะจง เช่น
   "ลองกดบันทึกตอนไม่มีเน็ต แล้วดูว่าข้อมูลยังอยู่ไหมค่ะ"
   ไม่ใช่แค่ "ลองดูนะคะ"

## กติกา

- **preview ไม่ใช่ทางลัดข้าม gate** — workflow จะไม่สร้าง URL ถ้า `npm run check` ไม่เขียว
  ถ้าไม่มี URL ออกมา ให้ไปดูว่า job `check` แดงที่ข้อไหนก่อน
- เวอร์ชัน preview **ไม่ได้อยู่บน production** จนกว่าจะ merge — บอกพี่ A ให้ชัดทุกครั้ง
  ไม่งั้นอาจเข้าใจว่าของขึ้นแล้ว
