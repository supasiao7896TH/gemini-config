# /ตรวจ — Quality Gate

> เรียกด้วย `/ตรวจ` เท่านั้น — ตั้ง `disable-model-invocation: true` เพราะคำว่า "ตรวจ"
> ใช้ในบริบทอื่นบ่อยมาก (ตรวจสอบค่า DCS, ตรวจงาน) ไม่ควร auto-trigger

## ลำดับการทำงาน

1. **เช็คว่าโปรเจกต์นี้มี `package.json` ไหม**
   - ไม่มี → บอกพี่ A ว่าโปรเจกต์นี้ยังไม่มี quality gate และเสนอให้ copy จาก
     `design-lab/starter-multifile/` (ค่าเริ่มต้น) หรือ `design-lab/starter/` ถ้าเป็น Single HTML File
     (ดู `vibe-coding-quality` §25.2) แล้วหยุด
2. **รัน `npm run check`** — ถ้าเครื่องนี้ลง Chromium ไม่ได้ ให้ใช้ `npm run check:local`
   แล้วบอกตรงๆ ว่า **ข้าม e2e ไป** จึงยังไม่ได้ตรวจ contrast/44px/โฟกัส
3. **รายงานผลทีละส่วน** ไม่ใช่แค่ "ผ่าน/ไม่ผ่าน":

   ```
   lint      ✅ / ❌ (ไฟล์ไหน)
   secrets   ✅ / ❌ (เจออะไร ที่ไหน)
   unit      ✅ 15 ผ่าน / ❌ ชื่อเทสต์ที่แดง + สาเหตุ
   e2e       ✅ 16 ผ่าน / ❌ ชื่อเทสต์ที่แดง / ⏭️ ข้าม (ไม่มี Chromium)
   ```

4. **ถ้าทุกอย่างเขียว → เรียก `sa-code-reviewer`** ต่อทันที
   เพราะเทสต์ตรวจสิ่งที่เขียนเทสต์ไว้แล้ว ส่วน reviewer ตรวจสิ่งที่ยังไม่มีเทสต์
5. **สรุปเป็น Definition of Done** (§25.3) ว่าข้อไหนผ่านแล้ว ข้อไหนยังต้องทำเอง
   — โดยเฉพาะ "เปิด preview URL บนมือถือจริง" ซึ่งเครื่องตรวจแทนไม่ได้

## กติกา

- **ห้ามรายงานว่าผ่านถ้ายังไม่ได้รันจริง** — แปะ output จริงเสมอ
- **ถ้าแดง ห้ามแก้เทสต์ให้ผ่าน** ให้แก้โค้ดที่ทำให้มันแดง
  ยกเว้นพิสูจน์ได้ว่าเทสต์เองเขียนผิด — กรณีนั้นต้องอธิบายให้พี่ A ฟังก่อนแก้
- **`npm test` ไม่ครอบคลุมหมวด ACCESSIBILITY/BRAND ของ §16** ห้ามสรุปว่าครอบคลุม
