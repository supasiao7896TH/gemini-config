# Claude Code CLI / VS Code — เทคนิคการใช้งาน

> รวบรวมจากบทสนทนาจริงกับ Claude — วันที่ 2026-08-08 หลังพี่ A บอกว่าติดใจใช้ Claude Code ผ่าน VS Code (จอดำ) มากกว่า claude.ai แล้ว

---

## เฉพาะตอนใช้ผ่าน VS Code

### 1. ใช้โหมด Diff แทนอ่าน terminal ดิบๆ
Claude Code extension บน VS Code โชว์การแก้ไฟล์เป็น diff view (แดง/เขียว) กด Accept/Reject ทีละไฟล์ได้เลย — เข้ากับโหมด "Accept Edits" ที่เป็น pattern แนะนำอยู่แล้วใน `skills/vibe-coding-workflow` §18.3

### 2. ให้ Claude อ่าน error จาก Problems panel ตรงๆ
ถ้า VS Code เชื่อมกับ Claude Code session อยู่ (IDE integration active) จะให้ Claude ดึง TypeScript/lint error จาก Problems panel ได้ตรงๆ ไม่ต้อง copy-paste error message ยาวๆ เอง (ตรงกับกฎที่ตั้งไว้ใน §18.5)
> ⚠️ ต้องมี IDE connection เชื่อมอยู่จริงในเซสชันนั้น — ถ้าปิด VS Code หรือ extension หลุดการเชื่อมต่อ ความสามารถนี้จะหายไปจนกว่าจะเชื่อมใหม่

### 3. แบ่ง terminal เป็น 2 ช่อง
ช่องนึงรัน dev server ค้างไว้ (เช่น `npm run dev`) อีกช่องคุยกับ Claude — เห็นผลเปลี่ยนแปลงสดๆ ไม่ต้องสลับหน้าต่างไปมา

### 4. โปรเจกต์ Single HTML File → เปิดคู่กับ Live Server
สำหรับโปรเจกต์ที่ยังเป็น Single HTML File (มาตรฐานเดิม) เปิด VS Code Live Server คู่กับ Claude Code ได้เลย แก้โค้ดแล้วเห็นผลในเบราว์เซอร์ทันทีโดยไม่ต้อง build

## Workflow / Keyboard shortcuts ทั่วไป (ใช้ได้ทุกที่ที่รัน Claude Code)

### 5. `/rewind` — undo ที่ปลอดภัยกว่า git
ถ้าลองอะไรแบบเสี่ยงๆ (โหมด "ลอง" ตาม §19) แล้วผลลัพธ์ไม่โอเค พิมพ์ `/rewind` ย้อนไฟล์กลับไปจุดก่อนหน้าได้เลย โดยไม่ต้องมี git commit รองรับไว้ก่อน

### 6. กด Esc สองครั้ง (double-tap) — แก้คำสั่งเก่าโดยไม่เสียรอบ
ถ้าพิมพ์คำสั่งไปแล้วรู้สึกว่าอธิบายไม่ครบ/พลาด กด Esc 2 ครั้งย้อนกลับไปแก้ข้อความที่พิมพ์ก่อนหน้าได้เลย ไม่ต้องเริ่มรอบใหม่หรือเสียบริบทที่มีอยู่

### 7. `@` mention ไฟล์ตรงๆ ในกล่องพิมพ์
พิมพ์ `@` แล้วเลือกไฟล์จาก autocomplete แทนอธิบายเป็นคำพูดว่าไฟล์อยู่ตรงไหน — แม่นกว่า ตรงกับกฎที่เขียนไว้เองใน §18.5 ("ระบุไฟล์ที่ต้องแก้ตรงๆ")

### 8. `/clear` เมื่อเริ่มงานใหม่ที่ไม่เกี่ยวกับเรื่องเดิม
เซสชันยาวๆ ที่คุยหลายเรื่องต่อกันกิน token เยอะขึ้นเรื่อยๆ — ถ้าจะเปลี่ยนไปทำเรื่องที่ไม่เกี่ยวกันเลย `/clear` ช่วยรีเซ็ตให้เบาลง

### 9. Shift+Tab สลับโหมดเร็วๆ ไม่ต้องพิมพ์
กด `Shift+Tab` วนสลับ Plan Mode ↔ Auto Mode ↔ Accept Edits ได้เลยกลางบทสนทนา เร็วกว่าพิมพ์สั่งเปลี่ยนโหมด

### 10. วางรูปภาพลงในกล่องพิมพ์ได้ตรงๆ
Screenshot UI, error message, หรือ mockup ที่ร่างด้วยมือ วาง (paste) ลงกล่องพิมพ์ได้เลย ไม่ต้อง save ไฟล์แล้วเปิดแยก — มีประโยชน์เวลาอยากให้ช่วยดูหน้าตาเว็บที่ทำ

### 11. `/cost` เช็คค่าใช้จ่ายเซสชันปัจจุบันแบบละเอียด
Statusline ที่ตั้งไว้ (`statusline.ps1`) โชว์คร่าวๆ อยู่แล้ว แต่ `/cost` แตกละเอียดกว่า เผื่ออยากรู้ว่า session ไหนกินโควต้าเยอะผิดปกติ

### 12. ใช้ subagent ที่มีอยู่แล้วก่อนเริ่มงานใหญ่ — ไม่ใช่แค่ตอน debug
พี่ A มี `sa-explore` (user-scoped ใช้ข้ามโปรเจกต์ได้) อยู่แล้วใน `agents/` — ก่อนเริ่มงานใหญ่ในโปรเจกต์ใหม่ บอกให้ `sa-explore` ช่วยสำรวจโครงสร้างก่อน จะประหยัด token ของ session หลักได้เยอะ เพราะการอ่านไฟล์เยอะๆ ไปกองอยู่ใน context ของ subagent แทน ไม่มากองใน context หลัก
